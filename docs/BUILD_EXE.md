# Сборка единого exe

Итог: один файл `Nomos.exe`, который запускается на машине без Python и
без установки зависимостей. Веб-интерфейс открывается в браузере.

Собирать нужно **на Windows**: PyInstaller не кросс-компилирует, exe
получается только на той ОС, где идёт сборка. Разрядность и версия
Windows у сборочной машины должны быть не новее целевой (собранное на
Windows 11 обычно идёт и на Windows 10, обратное — не всегда).

## Что понадобится

* Python 3.12 или 3.13, 64-бит (на 3.14 нет колёс pydantic-core — соберётся
  либо не соберётся, но работать не будет);
* доступ в интернет для установки пакетов (или заранее скачанные wheel).

## Сборка

```powershell
cd путь\к\nomos

python -m venv .venv
.\.venv\Scripts\Activate.ps1

pip install -r requirements.txt
pip install pyinstaller

pyinstaller nomos.spec
```

Готовый файл — `dist\Nomos.exe` (около 40–60 МБ). Папки `build\` и
`dist\` в git не попадают, они уже в `.gitignore`.

Есть скрипт, который делает всё перечисленное и сразу собирает папку
поставки: `powershell -ExecutionPolicy Bypass -File build_exe.ps1`.

## Что положить рядом с exe

Внутрь бандла запечён только код и статика веб-интерфейса. Всё, что
оператор правит или забирает, лежит снаружи:

```
Nomos\
├── Nomos.exe
└── configs\
    ├── .config.env            ← доступ к MaxPatrol (создаётся из example.config.env)
    ├── assets_filters.json
    ├── event_policies.json
    ├── table_filters.json
    ├── table_mapping.json
    ├── subrules.json
    ├── packages_names.json
    ├── policy_queries.json
    ├── bad_asset_file.json
    ├── asset_ids.txt
    └── dynamic_groups.txt
```

Папки `out\`, `logs\` и файл `nomos.db` программа создаст сама при
первом запуске — там же, рядом с exe.

Так сделано намеренно: конфиги экспертизы меняются между прогонами
(обновился knowledgebase — перегенерировали `event_policies.json`), и
запекать их внутрь означало бы пересобирать exe ради каждой правки.

## Запуск

Двойной клик по `Nomos.exe` или из консоли:

```powershell
.\Nomos.exe                       # http://127.0.0.1:8137
.\Nomos.exe --port 9000           # другой порт
.\Nomos.exe --host 0.0.0.0        # доступ с других машин (см. предупреждение ниже)
```

В окне консоли видно адрес, рабочую папку и ход прогона. Закрытие окна
останавливает сервер. Рабочей папкой всегда становится папка exe, откуда
бы его ни запустили — ярлык с другим «Рабочим каталогом» ничего не сломает.

**Про `--host 0.0.0.0`:** интерфейс не требует авторизации, а в конфиге
рядом лежит доступ к MaxPatrol. Открывать его в общую сеть не стоит;
если нужно работать с другой машины — пробрасывайте порт по SSH.

## Проверка перед передачей заказчику

1. Скопируйте `Nomos.exe` и `configs\` на машину **без Python**.
2. Запустите, откройте http://127.0.0.1:8137 — должна открыться страница
   «Запуски», а не пустой экран (пустой экран = статика не попала в
   бандл, проверьте секцию `datas` в `nomos.spec`).
3. Вкладка «Подключение» → «Проверить подключение»: так проверяется и
   чтение `configs\.config.env`, и сеть до MaxPatrol.
4. Запустите короткий прогон (один фильтр, `kb_check_mode` выключен) и
   скачайте XLSX — это проверяет запись в `out\` и работу xlsxwriter.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `ModuleNotFoundError` при старте | Модуль подгружается динамически и не попал в бандл. Добавьте его в `hiddenimports` в `nomos.spec` и пересоберите |
| Страница пустая, в консоли 404 на `/static/app.js` | Статика не попала в `datas`; проверьте, что собираете именно `nomos.spec`, а не `pyinstaller nomos_web.py` |
| «нет папки configs/» в консоли | Положите `configs\` рядом с exe |
| Антивирус удаляет exe | Обычная реакция на PyInstaller. Подпишите файл сертификатом организации или добавьте в исключения |
| Долгий старт (5–15 с) | Нормально для onefile: при каждом запуске бандл распаковывается во временную папку. Если мешает — соберите `--onedir` (папка вместо файла, старт мгновенный) |
| `SSLError` при подключении к MaxPatrol | Не связано со сборкой: сертификат стенда. Смотрите настройки подключения в README |

## Сборка CLI-версии

Для консольного прогона без веб-интерфейса есть отдельный скрипт: он
прогоняет тесты, собирает исполняемый файл и сразу складывает архив
поставки.

```powershell
powershell -ExecutionPolicy Bypass -File build_cli.ps1
```

В Git Bash — `./build_cli.sh`. Скрипты сами создают `.venv` рядом с
собой, ставят зависимости и PyInstaller и зовут
`tools/make_cli_release.py`; в сборку попадает только то, что нужно
консольной версии, а не всё, что стоит в системе.

На выходе `dist\NomosCLI_<дата>.zip`:

```
NomosCLI_20260915\
├── NomosCLI.exe
├── README.txt
└── configs\          (без .config.env — заполняется на месте)
```

Ключи: `--no-test` (пропустить тесты), `--out ФАЙЛ`, `--keep-build`.
Рецепт сборки — в `nomos_cli.spec`.

Рабочей папкой для exe всегда становится папка, где он лежит, поэтому
ярлык с другим «Рабочим каталогом» конфиги не потеряет.
